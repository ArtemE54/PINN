# Amazon Product Rating Classification

Проект по машинному обучению, который предсказывает, получит ли товар на Amazon высокий рейтинг (≥ 4.0), на основе его ценовых характеристик, текстовых описаний и метаданных отзывов.

## О проекте

Задача — бинарная классификация: по набору признаков товара определить, относится он к категории «хороших» (рейтинг ≥ 4.0) или «плохих» (рейтинг < 4.0). Проект охватывает полный цикл ML-пайплайна: от очистки «грязных» данных до сравнения нескольких алгоритмов классификации с подбором гиперпараметров.

## Данные

Используется датасет `amazon.csv` — выборка товаров Amazon с информацией о ценах, скидках, рейтингах, отзывах и категориях.

**Исходные признаки:**
- `discounted_price` — цена со скидкой
- `actual_price` — полная цена
- `discount_percentage` — процент скидки
- `rating` — рейтинг товара (целевая переменная до бинаризации)
- `rating_count` — количество отзывов
- `review_title`, `review_content`, `about_product` — текстовые поля
- `category` — категория товара

**Созданные признаки:**
- `price_diff` — разница между полной и скидочной ценой
- `review_title_len`, `review_content_len`, `about_product_len` — длины текстовых полей
- `review_word_count` — количество слов в отзыве
- `is_popular_category` — флаг популярной категории (Computers & Accessories / Electronics)

**Целевая переменная:** `is_good_rating` — бинарный признак, равный 1, если рейтинг ≥ 4.0, иначе 0.

## Методология

### 1. Очистка данных
Числовые поля в исходном датасете хранятся как строки с символами валюты (`₹`), запятыми и процентами. Функция `clean_numeric` удаляет эти символы и приводит значения к числовому типу. Строки с пропусками в ключевых колонках удаляются.

### 2. Разведочный анализ (EDA)
- Гистограмма распределения рейтингов с отмеченным порогом бинаризации
- Столбчатая диаграмма баланса классов
- Боксплоты для выявления выбросов в ценах, скидках и разнице цен
- Корреляционная матрица всех признаков для оценки мультиколлинеарности

### 3. Подготовка данных
Стратифицированное разделение на train/test (80/20) с сохранением пропорций классов. Признаки стандартизируются через `StandardScaler`.

### 4. Моделирование
Три алгоритма классификации с подбором гиперпараметров через `GridSearchCV` (5-fold CV, метрика — F1):

| Модель | Пространство поиска |
|---|---|
| Logistic Regression | `C`, `penalty`, `solver` |
| SVM | `C`, `kernel`, `gamma` |
| kNN | `n_neighbors`, `weights` |

### 5. Оценка качества
Модели сравниваются по метрикам: Accuracy, Precision, Recall, F1, ROC-AUC. Строится ROC-кривая для всех трёх моделей.

## Результаты

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| Logistic Regression | 0.761 | 0.760 | 1.000 | 0.864 | 0.668 |
| SVM | 0.765 | 0.774 | 0.973 | 0.862 | 0.671 |
| kNN | 0.761 | 0.779 | 0.955 | 0.858 | 0.733 |

Все модели показывают близкие результаты по F1 (~0.86), однако **kNN** имеет заметно более высокий ROC-AUC (0.733), что говорит о лучшем качестве ранжирования вероятностей. Высокий Recall у всех моделей объясняется дисбалансом классов (75.9% «хороших» товаров): модели склонны предсказывать положительный класс.
